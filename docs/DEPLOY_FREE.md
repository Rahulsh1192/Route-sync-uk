# Test Routify — Go Live for Free

A step-by-step guide to deploy the **current phase** of Test Routify at zero cost, using
only free tiers. No servers to manage; everything deploys from your GitHub repo.

> **What works free:** web app (including the admin console at `/admin`), API, database, auth, the Test Centres module,
> and the access rules (per-centre paywall, one free demo route).
> **What doesn't:** the Python media **worker** (video/AI processing) — too heavy for
> free tiers, so **uploading/processing new routes is disabled**. Browsing seeded
> routes, login, the gates, the paywall, and practice mode all work.
>
> **Expect:** the free API sleeps after ~15 min idle (first request wakes it, ~30–60s);
> the free database pauses after inactivity and wakes on the next request. Fine for
> testing/demos.

---

## The stack (3 new free accounts + Vercel)

| Part | Tool | Free tier |
|---|---|---|
| Database (Postgres **+ PostGIS**) | **Supabase** | 500 MB; pauses when idle |
| Redis (job queue/cache) | **Upstash** | Serverless, generous free |
| API (`apps/api`) | **Render** (Web Service) | Sleeps when idle |
| Web app (`apps/web`) | **Vercel** | Static hosting from repo (admin console at `/admin`) |
| File storage (optional) | Cloudflare **R2** | Only if you enable uploads |

Helper files already in the repo:
- [`db/bootstrap.sql`](../db/bootstrap.sql) — the whole database in one paste (verified).
- [`render.yaml`](../render.yaml) — API service definition for Render.
- [`apps/web/vercel.json`](../apps/web/vercel.json) — routes `/api` calls to your API.

## Step 1 — Database (Supabase)

1. Create a free account → **New project** (pick a region near you, set a DB password).
2. Open **SQL Editor** → run once:
   ```sql
   create extension if not exists postgis;
   ```
3. Open [`db/bootstrap.sql`](../db/bootstrap.sql), copy **the whole file**, paste into a
   new SQL Editor query, and **Run**. It creates every table and loads demo data
   (7 users, seeded routes, 45 test centres).
4. Apply the Phase 20 migration: open [`db/migrate_phase_20.sql`](../db/migrate_phase_20.sql),
   paste into a new query, and **Run** (adds `test_centres.address`/`description` and the
   `routes.test_centre_id` index). Optionally also run
   [`db/seed_test_centres_demo.sql`](../db/seed_test_centres_demo.sql) for extra demo
   test-centre content.
5. Go to **Project Settings → Database → Connection string → URI**. Copy it — this is
   your **`DATABASE_URL`**. (Append `?schema=public` if it isn't there.)

## Step 2 — Redis (Upstash)

1. Create a free account → **Create Database** (Redis) → pick a region.
2. Copy the connection URL (the `redis://…` / `rediss://…` string). This is **`REDIS_URL`**.

## Step 3 — API (Render)

1. Create a free account → **New → Blueprint** → connect this GitHub repo. Render reads
   [`render.yaml`](../render.yaml) and sets up the `routesync-api` service.
2. When prompted, fill the secret env vars:
   - `DATABASE_URL` = from Step 1
   - `REDIS_URL` = from Step 2
   - The `S3_*` vars come pre-filled with placeholders in `render.yaml` — leave them.
     (The API requires them to boot; they only need real Cloudflare R2 values once you
     enable uploads.)
   The JWT secrets are generated automatically.
3. Deploy. When it's live, note the URL, e.g. `https://routesync-api.onrender.com`.
4. Test it: open `https://YOUR-API.onrender.com/api/health` — you should see
   `{"status":"ok","db":"up"}`.

## Step 4 — Web app (Vercel)

Just one project — the admin console ships inside the web app at `/admin`.

1. Create a free account → **Add New → Project** → import this repo.
2. Set **Root Directory** to `apps/web`.
   Framework preset: **Vite**. Build/output are already in `vercel.json`.
3. **Before deploying**, edit the `destination` in `apps/web/vercel.json` (or do it
   after) so it points at **your** Render URL from Step 3:
   ```
   https://routesync-api.onrender.com/api/:path*   →   https://YOUR-API.onrender.com/api/:path*
   ```
4. Deploy. Your web app is live at a `*.vercel.app` URL (admin console at `/admin`).

> The `vercel.json` rewrite makes the browser call `/api/...` on the same domain, and
> Vercel proxies it to the API server-side — so **no CORS setup is needed**.

## Step 5 — Try it

Open your web app's URL and sign in with a seeded account (password **`Password123!`**):
`learner@routesync.uk`, `demo@routesync.uk` (admin), `instructor@routesync.uk`.

## Environment variables reference

Set on the **API** (Render). Only the first two are strictly required to boot.

| Variable | Required? | Where it comes from |
|---|---|---|
| `DATABASE_URL` | ✅ | Supabase connection string |
| `REDIS_URL` | ✅ | Upstash connection URL |
| `JWT_ACCESS_SECRET` / `JWT_REFRESH_SECRET` | ✅ | Auto-generated by `render.yaml` |
| `NODE_ENV` | ✅ | `production` (already in `render.yaml`) |
| `S3_ENDPOINT` / `S3_ACCESS_KEY` / `S3_SECRET_KEY` / `S3_BUCKET` | ⬜ | Cloudflare R2 — only for uploads/video |
| `STRIPE_SECRET_KEY` / `STRIPE_WEBHOOK_SECRET` / `STRIPE_PRICE_*` | ⬜ | Stripe (keep in **test mode**; free) |
| `GOOGLE_CLIENT_ID`, `APPLE_*` | ⬜ | Only for social login |
| `SENTRY_DSN` | ⬜ | Only for error monitoring |

The **frontend** needs no env vars — the `/api` rewrite in `vercel.json` handles the API URL.

## Gotchas (specific to this app)

- **PostGIS is required** — that's why Supabase/Neon, not just any free Postgres.
- **Relative `/api` paths:** the frontends call `/api/...` with no host. The `vercel.json`
  rewrite is what connects them to the API. Without it, the live site can't reach the API.
- **Render build & dev deps:** `render.yaml` uses `npm install --include=dev` on purpose —
  without it, `NODE_ENV=production` makes npm skip the build tools and the build fails.
- **Seed placeholder UUIDs:** a few seeded test centres use non-standard UUIDs and won't be
  selectable in forms. Real centres (the 45 in the picker) work fine.
- **Payments:** keep Stripe in **test mode**. Real charges need live keys and a business.
- **Uploads/worker:** disabled on free tiers. To enable later you'd add Cloudflare R2 and a
  paid worker host.
