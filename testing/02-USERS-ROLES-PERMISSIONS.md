# 02 — Users, Roles and Permissions

Every statement here is taken from the implementation. Role names in this application do
**not** carry their usual industry meanings — read this document before assuming anything.

---

## 1. Where roles are defined

| Layer | Definition |
|---|---|
| Database | `CREATE TYPE user_role AS ENUM ('user','contributor','instructor','moderator','admin');` — [db/schema.sql:23](../db/schema.sql) |
| API | `UserRole` enum generated by Prisma — [apps/api/prisma/schema.prisma](../apps/api/prisma/schema.prisma) |
| API enforcement | `@Roles(...)` + `RolesGuard` — [roles.guard.ts](../apps/api/src/common/guards/roles.guard.ts) |
| Web — "staff" | `isStaffRole(role)` → **`instructor` or `admin` only** — [apps/web/src/api/types.ts](../apps/web/src/api/types.ts) |
| Web — admin console | `isAdminRole(role)` → **`admin` or `moderator`** — [apps/web/src/App.tsx](../apps/web/src/App.tsx) |
| Web — can apply as ADI | `canApplyAsInstructor(role)` → **`user` or `contributor`** — [apps/web/src/api/types.ts](../apps/web/src/api/types.ts) |

**There is exactly one role per user.** There is no permission table, no role hierarchy,
and no per-user permission grants. `RolesGuard` does a flat membership test:
`required.includes(user.role)`. A role is either listed on the endpoint or it is denied.

> This matters: `admin` is **not** automatically allowed everywhere. It is allowed only
> where `@Roles('admin')` (or a class-level default including it) is present. For example
> `@Roles('instructor')` on the instructor availability endpoints means an **admin cannot
> add availability slots** via the API.

The role is embedded in the **access token** at login. A role changed by an admin does
**not** take effect for the affected user until their access token is refreshed or they
log in again — see [07-EDGE-CASES.md](07-EDGE-CASES.md), `EDGE-014`.

## 2. The five roles at a glance

| Role | Real meaning in this app | Post-login landing | Navigation shown | Detail |
|---|---|---|---|---|
| `user` | Default learner. Watches routes, books lessons. | `/test-centres` | Learner | [roles/user-learner.md](roles/user-learner.md) |
| `contributor` | **Behaves exactly like `user`.** No endpoint anywhere grants `contributor` anything a `user` lacks. Used as a marker for accounts with a pending ADI application. | `/test-centres` | Learner | [roles/contributor.md](roles/contributor.md) |
| `instructor` | Verified ADI. Uploads routes, manages test centres, sets availability, receives bookings. Limited to one active session. | `/test-centres` | Staff | [roles/instructor.md](roles/instructor.md) |
| `moderator` | Admin console with the *sensitive* actions removed. Can review and approve content, but cannot change users, see revenue, or move money. | `/admin` | **Learner** (see warning below) | [roles/moderator.md](roles/moderator.md) |
| `admin` | Everything the console offers, plus the instructor's content abilities. | `/admin` | Staff | [roles/admin.md](roles/admin.md) |

> ⚠ **Moderator navigation anomaly (verified in code).** `AdminProtected` admits
> `moderator`, so a moderator reaches `/admin`. But `isStaffRole()` excludes `moderator`,
> so when a moderator clicks "Main app" they get the **learner** navigation — no
> Contribute tab, and no "New test centre" button. This is consistent with the API (the
> test-centre write endpoints are `@Roles('instructor','admin')`, excluding moderator),
> so it may be intentional. Flagged as `Needs Clarification` in
> [13-TESTING-GAPS.md](13-TESTING-GAPS.md).

## 3. What each role can do — summary

The authoritative, action-by-action table is
[03-ACCESS-CONTROL-MATRIX.md](03-ACCESS-CONTROL-MATRIX.md). This is the summary.

### 3.1 `user` (learner)

**Can:** browse and search test centres and routes; open one route free (permanently
claimed); watch/practise routes at a centre they hold Premium for; buy Premium; search
and book instructors; view and cancel their own bookings; view their own progress;
edit their own profile and contact details; request a GDPR export or erasure; apply to
become an instructor.

**Cannot:** upload routes, create/edit/delete test centres, create reference routes,
start journeys, access `/admin`, see any other user's data.

### 3.2 `contributor`

**Identical to `user` in every enforced permission.** Searched the whole API: no
`@Roles(...)` list anywhere contains `contributor`. The only behavioural difference is on
the web Account page, where `canApplyAsInstructor()` treats `user` and `contributor`
alike — so the "Become an instructor" call to action is shown to both.

In the seed data, `contributor` marks the three accounts with **pending** ADI
applications.

### 3.3 `instructor`

Everything `user` can do, plus:

- Create / edit / **delete** test centres (`@Roles('instructor','admin')`).
- Postcode lookup helper for the test-centre form.
- Create reference routes (R1), start / check / submit journeys, list their own journeys.
- Initiate uploads, sign multipart parts, complete or abort uploads, attach video to an
  existing map-only route.
- Manage their own instructor profile (bio, price, years, accepting-bookings flag, base
  postcode, travel radius).
- Add / list / delete their own availability slots.
- See the bookings made with them.
- Update the status of a booking they are party to.

**Cannot:** access `/admin`; moderate routes; see other instructors' bookings or slots.

**Single session:** logging in anywhere revokes all other instructor sessions.

### 3.4 `moderator`

Reaches `/admin` and can use these console endpoints (class-level
`@Roles('moderator','admin')` on [admin.controller.ts](../apps/api/src/modules/admin/admin.controller.ts)):

Review queue · route detail · **moderate (approve/reject)** · analytics ·
users **list** (read-only) · pending instructors · instructor evidence ·
**verify instructor** · reports · moderation log · fund summary · fund beneficiaries
(list) · revshare runs / instructors / run detail · all bookings.

**Explicitly denied** (endpoints tightened to `@Roles('admin')`):
`GET /api/admin/revenue` · `PATCH /api/admin/users/:id` · `POST /api/admin/fund/allocate`
· `POST /api/admin/fund/beneficiaries` · `POST /api/admin/fund/payout` ·
`POST /api/admin/fund/run-contribution` · `POST /api/admin/revshare/run`.

**Also denied** (moderator is not in the `@Roles` list): all test-centre writes, all
uploads, all journeys/reference-route writes, all instructor-availability endpoints.

> The Revenue panel in the console will therefore fail with **403 Forbidden** for a
> moderator. The console does not hide the nav item. That is a UI/API permission
> inconsistency worth raising — see **PI-06** in [13-TESTING-GAPS.md](13-TESTING-GAPS.md); the API-level test is `PERM-018`.

### 3.5 `admin`

The full admin console (every endpoint above, including the admin-only ones), **plus**
the instructor content permissions (`@Roles('instructor','admin')` covers uploads,
test-centre writes, reference routes and journeys).

**Not granted:** the instructor-only availability endpoints
(`@Roles('instructor')` on `instructors/me/profile`, `/slots`, `/bookings`) — an admin
calling these gets **403**. Confirmed in [bookings.controller.ts](../apps/api/src/modules/bookings/bookings.controller.ts).

## 4. Data / resource visibility (access scope)

| Resource | Who can see which rows |
|---|---|
| Routes (learner-facing) | Only `status = 'published'` and `deleted_at IS NULL` |
| Route video / track / instructions | Only with a satisfied access decision (Premium for that centre, or the claimed demo route) |
| Uploads | Only the uploader — `getOwned()` throws `Not your upload` |
| Journeys (recorded drives) | `GET /api/journeys/:id` takes the caller's id **and role**; `listInstructorJourneys` is scoped to the caller |
| Bookings — learner | `WHERE learner_id = <caller>` |
| Bookings — instructor | `WHERE instructor_id = <caller>` |
| Booking update | Allowed if caller is the learner, the instructor, **or** `admin`/`moderator` |
| Availability slots (own) | `WHERE instructor_id = <caller>`; deleting a **booked** slot is refused |
| Availability slots (public) | Only future, `is_booked = FALSE` |
| Progress / history / offline packages / notifications | Scoped to the caller's user id |
| Instructor search results | Only `role = 'instructor'` **and** `instructor_status = 'verified'` **and** `is_suspended = FALSE` **and** accepting bookings |
| Instructor public profile | Only where `instructor_status = 'verified'` |
| ADI badge evidence | Admin/moderator only, via a **300-second** signed URL |
| Admin users list | All non-deleted users, limit 50, includes phone + emergency contact |
| Admin bookings | All bookings, 50 per page |

## 5. Account states

| State | Column | Effect |
|---|---|---|
| Suspended | `users.is_suspended` | Login is refused with `Account suspended`. Also refused on the OAuth path. Excluded from instructor search. **An existing access token keeps working until it expires** — see `EDGE-015`. |
| Soft-deleted | `users.deleted_at` | Excluded from the admin users list and the user count. Password reset is silently refused. |
| Email verified | `users.email_verified` | Required for a Google/Apple identity to auto-link to an existing account. **Not** required to log in or use the app. |
| Instructor status | `contributors.instructor_status` ∈ `none`/`pending`/`verified`/`rejected` | Only `verified` appears in instructor search and has a public profile |

## 6. Role transitions

| From | To | Trigger |
|---|---|---|
| *(none)* | `user` | Registration — `users.role` defaults to `user` |
| `user` / `contributor` | `instructor` | Admin/moderator approves the ADI application: `verifyInstructor(..., 'verified')` sets `users.role = 'instructor'` and `contributors.instructor_status = 'verified'` |
| any | any | Admin changes the role directly in the Users panel (`PATCH /api/admin/users/:id`, `@Roles('admin')`) |

Rejecting an ADI application sets `instructor_status = 'rejected'` and **does not change
`users.role`**.

`Needs Clarification`: nothing in the code demotes a user from `instructor` when their
ADI badge expires. `adiExpired` is surfaced to the UI, but no enforcement was found.
